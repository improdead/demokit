# DemoKit release-readiness audit — 2026-09-04

Scope: code and skill review, npm 0.3.0 metadata/tarball, clean-prefix installation,
GitHub documentation, public alternatives research, and candidate regression tests.
This document distinguishes tested behavior from claims and unresolved work.

## Assessment

A useful working prototype with substantial functionality, but the published 0.3.0
package should not yet be described as a polished, uniquely capable, fully audited
release. The successful Trident demo used an adapted Playwriter capture script;
that is evidence the components can work, not proof of effortless packaged setup.
The original skill was 1,032 lines and mixed operating instructions with historical
rendering experiments. It had useful evidence principles but too much stale detail.

## Release blocker: renderer provenance and license

`src/caprender.py` describes porting Cap rendering algorithms, function behavior,
constants, and spring/cursor/composition mechanics from `crates/rendering`.
DemoKit's `LICENSE` and npm metadata declare MIT. Cap's
[license](https://github.com/CapSoftware/Cap/blob/main/LICENSE) limits its MIT
exceptions to the `cap-camera*` and `scap-*` crate families; other covered code is
AGPLv3. `crates/rendering` is not listed as an MIT exception.

This is concrete provenance evidence requiring resolution, not a definitive legal
opinion about each implementation detail. The current audit does not certify the
renderer as MIT-compatible. Before publishing another release, trace the actual
adaptations and choose an authorized licensing/compliance path, obtain appropriate
permission, or replace the dependent implementation with a demonstrably independent
renderer. Do not silently relabel upstream work as MIT or change the owner's
license choice without authorization. No npm publish is part of this candidate.

## Remaining limits

- **History:** generated captures were removed from the current Git tree, but were
  previously committed. Ignore rules and deleting current files do not remove Git
  history. Any history rewrite and remote cleanup require a separate explicit decision.
- **Capture parity:** legacy real-Chrome capture lacks the local recorder's complete
  semantic evidence. The successful ad hoc adapter is not yet a shared packaged engine.
- **Viewport geometry:** local CSS zoom can change viewport-unit/fullscreen layouts.
  Device-scale capture worked in the audited Playwriter session, but is not yet the
  default recorder. Full-document navigation can lose hide/redact/zoom decorations.
- **Renderer configuration:** legacy compositor knobs and `edit.json` are not all
  effective in the Cap-style renderer. Check the actual exported frames.
- **Legacy command paths:** terminal/native/wallpaper helpers still have checkout-
  relative assumptions. Use a checkout for those modes. Optional renderer config,
  assets, and critic patch files should use absolute paths. The package smoke
  covers the default local route, not every older subcommand.
- **Concurrency:** each concurrent job needs a separate work directory. Reusing a
  flow name replaces its take. The release does not claim a resumable job service.
- **Platforms/dependencies:** Python and Linux system libraries are prerequisites;
  npm can block FFmpeg's download script. Native recording is macOS-only; Docker
  capture is experimental. Windows is unsupported.
- **Verification:** heuristics require interpretation. Successful encoding, a DOM
  change, or camera geometry alone is not proof of the requested feature.
- **Distinctiveness:** close alternatives exist; see [the dated comparison](ALTERNATIVES.md).

## Validation

The published 0.3.0 tarball installed in a fresh temporary prefix; `--help` then
reproduced exit 1. Candidate CLI regressions were written first and failed before
implementation. Six CLI/package tests passed locally; the installed-tarball smoke
passed probe, capture, render, verification, relative re-render, and a failed-assertion
case from a directory with spaces. Exported frames were visually inspected. The
skill passed the skill validator. `npm audit --omit=dev` reported zero known
advisories; this is not a complete security audit. CI results are recorded in the PR.
No production application mutation, recording upload, history rewrite, token
rotation, license change, or npm publication was performed as part of this audit.
